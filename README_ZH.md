# E2EE-Experiment
简体中文 | [English](README.md) | [AI 协作文档](README_AGENT.md)

> 一个二进制，像一个人：能听，能说，转身即忘。也能围一张桌——
> 群聊的一切规矩，都从物理对话的规矩翻译而来。

**E2EE-Experiment** 把一个比喻当了真：*可执行文件就是一个人。*
没有服务器，没有账户，没有数据库——只有一个替你保守秘密、聊完就忘的程序。

> **使用 AI 助手（Copilot / Claude / GPT 等）参与本项目的开发？** 请先阅读
> [README_AGENT.md](README_AGENT.md)——它专为 AI 编写，包含本项目的设计不变量
> 与红线约束，跳过它直接改代码极可能破坏零持久化内核。

## 这是什么

| 人                   | 程序                                 |
|----------------------|--------------------------------------|
| 耳朵                 | 出生即打开 —— 进程一启动就守在端口上 |
| 嘴                   | `/dial` —— 随时主动找人，不必重启    |
| 只有你们俩听得懂的话 | 端到端加密 —— 每场对话全新的钥匙     |
| 一张桌子             | `/circle` —— 名单即桌子，围坐即成圈  |
| 转身即忘             | 零持久化 —— 任何东西都不落盘         |
| 认出对面是谁         | **你自己来**，解密之后               |

最后一行是刻意为之。这是安全里的**电话模型**：线路是保密的，
但听筒那头自称是谁，就是谁。系统只承诺**保密**，从不承诺**身份**——
加密从来不等于认证。认出声音——靠暗语、共同记忆、对一遍短词——是人类的
本事，就留在人类手里。（想把这步做扎实，见[暗号与对词](#暗号与对词确认对面是谁)。）

## 工作原理

三件事撑起全部安全性：

1. **每场对话都是一把新钥匙。** 每条连接都现场做一次全新的密钥交换——
   攻击者必须**同时攻破**经典算法（X25519）**和**后量子算法（Kyber1024）
   才能读到任何内容：即使有人把今天的流量录下来、等着量子计算机出现，
   也一无所获。对话结束，钥匙随之即焚——前向保密是白送的。
2. **任何东西都不落盘。** 不写配置、不写日志、不存密钥、不留历史。
   进程就是寿命——退出即死亡，死亡即遗忘。
3. **人人平等。** 每份拷贝完全相同，没有服务器/客户端之分，没有特权节点。
   用于 NAT 穿透的可选"茶馆"只搬运它自己都读不懂的字节。

**诚实的威胁模型。** *能防：*线路上的人（ISP、嗅探 Wi-Fi 的人、骨干网
窃听）——他们看到的只有加密帧。*不防（默认）：*主动中继握手的中间人
（电话模型接受的代价——暗号可以堵住它，对词可以当场查出它，见
[暗号与对词](#暗号与对词确认对面是谁)），以及对端本人（对方可以复制、
粘贴、截图）。

### 值得知道的关键细节

- **流量形状混淆**——握手帧和聊天帧带随机垫、文件按随机大小切块：
  同一句话连发八次，八种帧长。被动观察者无法从尺寸指纹读出内容。
- **文件从不走文字车道**——二进制一毫不差地到达，不被文本检查损坏，
  单文件上限 32MB。
- **群里没人能替别人开口**——每个成员入场时带一把一次性嗓音钥：
  圈内发言、告别、引荐、作证全部署名，名单行是本人自签的。
- **有人离席/入席就换气（换钥）**——离开的人从此解不开新话，入座的
  人翻不出旧账：钥匙的边界就是桌子的边界。没有花名册可泄露，
  因为从未存储过。
- **上屏的名字永远取自来线，不取自明文**。
- **关掉即遗忘，这就是胁迫防御的全部**——不落盘（零持久化）、密钥与
  明文在内存中用后即焚、每场对话的钥匙都是临时的：正常退出后，翻遍
  整台机器也找不到一句话。没有「胁迫模式」，也不需要——从来没有可被
  翻出的历史。诚实边界：被 kill -9 或断电强杀的瞬间存在秒级内存残留
  （重启即消散）；被缴的、正在运行的设备自然读得到正在说的话——任何
  实时通信皆然，关掉即止。

## 上手

两种方式拿到程序：

- **预编译**——从 [GitHub Releases](https://github.com/Huai-Tian/E2EE-Experiment/releases)
  下载：完全静态的 Linux x86_64（musl，零运行时依赖）、Linux glibc 版、Windows 版。
- **源码构建**——`cargo build --release`，产物在 `./target/release/E2EE-Experiment`。

第一场对话，同一台机器开两个终端：

```bash
# 终端 1 —— Alice 出生，默认在 7777 上听
./target/release/E2EE-Experiment -n Alice

# 终端 2 —— Bob 出生在自己的端口上，然后走去找 Alice
./target/release/E2EE-Experiment -n Bob 127.0.0.1:7778
/dial 127.0.0.1:7777
```

敲一行回车，这一行就会（在途中加密）出现在对面。聊天走 stdout、
连接事件走 stderr——对话本身可以直接接管道。收到的文件落在 `./received/`。

### 启动选项

```
E2EE-Experiment [监听地址] [-n 名字] [选项]
```

| 选项            | 含义                                                                                                                                |
|-----------------|-------------------------------------------------------------------------------------------------------------------------------------|
| *（无）*        | 出生即监听 `0.0.0.0:7777`。同一台机器开两个人要换端口。                                                                             |
| `-n <名字>`     | 自报家门的显示名（别名而已，背后没有任何背书）。                                                                                    |
| `--no-chain`    | 道别不预约下一把暗号、也不接受别人的预约——对陌生人常开的台席用这个。                                                                |
| `--guard <KEY>` | 常备门禁：每位来客都要对上同一句机器暗号（32 字节随机串），且从不消耗——错钥拨号刷多少次也锁不住台。与 `--no-chain` 同用即武装台席。 |
| `--courier`     | 开茶馆（见[两堵 NAT 墙之后](#两堵-nat-墙之后)）——同一个二进制的另一份工。                                                           |

### 指令一览

| 指令                                | 作用                                                                         |
|-------------------------------------|------------------------------------------------------------------------------|
| `/dial <地址> [暗号]`               | 主动去找人；带暗号则双方必须对上。                                           |
| `/await <暗号>`                     | 备好切口：下一位来客对得上才谈得成（一位一验、验完即焚——端口扫描烧不掉它）。 |
| `/meet <茶馆地址> <房号> [暗号]`    | 经茶馆与事先约好的人碰头（双方报同一房号）。                                 |
| `/punch <介绍人地址> [标签] [暗号]` | 经介绍人尝试 UDP 打洞**直连**。标签可省略：自动生成 128bit 新标签上屏（Crockford base32 分组，带外转告给对方）；显式短标签会响亮警告但照用（若带暗号，由 PAKE 层兜底）。 |
| `/file <路径>`                      | 递一份文件（≤32MB）给当前对话的人。                                          |
| `/talk <编号\|名字>`                | 在多场并行对话间切换注意力。                                                 |
| `/list`                             | 看当前连着谁。                                                               |
| `/card`                             | 打印自己的名片（名字 + 各网卡地址）。                                        |
| `/circle [封桌\|开台] [名1 名2 …]`   | 围坐成圈：不带名字 = 邀请当前连着的全部人；指定名字 = 选择性开圈（只邀这几条线，旧桌保留）。在圈中重跑 = 点名重聚（修复路径）。多人默认封桌、一人默认开台。 |
| `/gsay <话>`                        | 圈内发言——署名 + 加密一次，人人同时收到。                                   |
| `/bring [拟名]`                     | 领人入座：向当前对话的人（候选人）递看座骨架。带拟名则开期望门。             |
| `/sit [名字]`                       | 落座：回应看座邀约（落座署名必须本人触发）。                                 |
| `/word`                             | 对词：显示当前信道的短词（会话短词 / 群短词）。                             |
| `/bye`                              | 与当前对话的人道别（在圈则先署名告退）。                                     |
| `/quit` 或 Ctrl-D                   | 与所有人道别后离场；Ctrl-C 直接离场。                                        |

### 群聊：围一张桌

1. **围坐**——任何人对**当前连着的人**跑 `/circle`：一份署名邀请名单
   （她亲眼看见的在场，不是任何人的权威名册）。名单上的名字各自带来
   一份自签的随机贡献，**到齐即铸群钥**：无人能独断，也无人能预知。
   不必人人互连——成员之间连得通就行（星形、链形都欢迎），话会沿着
   名单走到每个人。
2. **发言**——`/gsay <话>`：一次性嗓音钥署名 + 群钥加密，一份密文
   沿成员间的线逐跳转达。多人默认**封桌**（领人入座要全员认账），
   一人默认**开台**（想要观众就开个台）；`/circle 封桌|开台` 可显式
   覆盖。
3. **对词**——`/word`：圈内显示群短词（12 位数字分 4 组，全员相同）。
   想确认这桌没被人动过手脚，就口头对一遍。
4. **入席**——在座的人 `/bring`（领人入座），对方 `/sit`（落座自签）：
   看座 → 落座 → 换气 → 座次表，四步走完新人即刻入圈——她读得到
   入座之后的话，翻不出入座之前的历史。
5. **离席**——`/bye` 是署名告别：握着她直连线的邻居作证补话，
   全桌换气——离开的人从此解不开新话。掉线（断电、拔线）同理：
   死线的持有者作证。换气只封存未来，不假装能收回已说出的话。
6. **修桌**——任何不一致（有人同时改名单、有人的话解不开——「圈语」
   响亮提醒）都由同一个动作修复：重跑 `/circle` **点名重聚**。
   新圈号、重新到齐、一切抚平。协议不假装永远一致，只保证：
   **分歧必被听见，修复永远可得。**

### 两堵 NAT 墙之后

你们俩都能**拨出**——NAT 从不拦出门，问题只在谁接电话。两个答案都内置了：

- **茶馆**——在有公网 IP 的机器上以 `--courier` 跑同一个二进制。它不是特权
  服务器：无身份、无存储、无明文。带外约好同一房号的两位客人被接到一起。
  它看得见谁、何时、多少字节——一个字也看不见。
  ```bash
  # 公网机器上
  ./E2EE-Experiment --courier 0.0.0.0:8888
  # 两边各自从 NAT 墙后
  /meet <茶馆地址> <房号> [暗号]
  ```
- **介绍人（打洞）**——茶馆的 UDP 兼职。想要**直连**的两个人报同一个
  标签，各自得知对方的公网地址，然后同时敲对方的门——各自的 NAT 都以为
  是自己人先出的门，把门开着。尽力而为：墙太严打不通，就手动换 `/meet`
  走茶馆，没有自动回退。

**房号和标签是接头地点，不是秘密**——要挑得难猜（两对人撞号会被接到
一起），并且像暗号一样带外约定。

### 暗号与对词：确认对面是谁

中间人漏洞的解药是两个人类动作——**暗号**防患于前，**对词**察觉于后：

- `/dial <地址> <暗号>`——握手从此包含一个数学证明：双方持有**同一句**
  暗号。暗号本身从不在任何线上以可推导的形式出现；对不上响亮失败；
  离线爆破不存在。
- `/await <暗号>`——等人来之前，在自己这头备好。
- **暗号链**——道别时可以在已认证的信道里预约下一把暗号，明天的对话
  自动重新认证。它只活在内存里；重启就回到带外再念一次。对陌生人常开
  的台席用 `--no-chain` 整个退出。
- **对词（`/word`）**——不带暗号也有一道保险：聚焦 1:1 时显示**会话短词**
  （两端相同），在圈时显示**群短词**（全员相同），两者兼有时都报。
  12 位数字分 4 组，电话里念一遍几十年验证过的仪式。中间人把一条线
  拼成两半 ⇒ 两把钥匙 ⇒ 两半短词不同 ⇒ 一念即穿。短词即时计算、
  永不落盘；不对账也没关系——它是给愿意谨慎的人的工具，不是义务。
- **弱暗号只伤害握手那一瞬**——暗号从不加密对话本身；每场对话的钥匙
  都是全新的临时密钥。

## 已知限制

- **没有存活探测。** 对端不辞而别（断电、拔线，或打洞 UDP 线——UDP 天生
  没有 EOF），那条线和 `/list` 里的条目会一直挂到 `/quit`。圈里的僵尸
  成员由其直连邻居的见证换气清出。
- **介绍人的引荐不认证。** 谁知道标签，谁就能顶替"另一头"报名——
  要确认对面是谁，带暗号。
- **茶馆只按房号配对。** 房号要挑得难猜。
- **圈子的载体看得见桌子的物理。** 茶馆/网络能看到圈的存在、流量形状
  与成员间的转发拓扑（圈号是明文路由信息）——它读不到一个字的内容。
  这是"桌子的物理被茶馆继承"，诚实入档。
- **群一致性靠点名。** 分歧不隐藏——解不开的话以「圈语」响亮提醒；
  任何成员重跑 `/circle` 即重聚。星形圈的枢纽离场后，其余人需要
  点名重建。一个进程同时只坐一个圈。
- **跨版本：对话照旧，圈子断代。** 带垫聊天帧对旧版本不可见（沉默
  跳过，不显乱码）；旧→新照常可读；但 3.0.0 的圈子帧布局与 1.x
  互不相认（这正是断代升级的原因）。1:1 对话两端一起升级最好。
